반도체 지식·논문 리서치 검증 체계

← 목차 · 2026-10-09 v1

지금까지는 Claude(작성) + astra(다른 계열 모델 자문) + jev(판단 API)를 그때그때 불렀다. 그러다 보니 쓴 쪽이 스스로 검증해 오류가 늦게 발견됐다 — 예: 교과서 모델 수치를 일반값처럼 쓰기, 이온 에너지를 V로 표기, EUV DRAM 도입 연도 혼동(용어 검토 #38에서 51개 용어 수정). 이 체계는 "찾기 → 주장 장부 → 분리된 검증 → 규칙 기반 채택"을 반복 가능한 절차로 만든다.

절차

질문 정리하위 질문·기준일·고위험 주장
수집paper-scout 에이전트(중립 질문만) + 학술 DB 검색
주장 장부한 문장 한 사실, 단위·조건·사건 종류·원문 접근 범위
기계 검사단위·날짜·조건 lint, DOI·URL 실재 확인
분리된 검증claim-verifier — 주장만 받고 웹 원문 대조
규칙 채택gate가 채택·조건부·보류·제외 결정

역할과 권한

구성하는 일하지 않는 일 / 막는 방법
Claude (조율·작성)질문 정리, 장부 작성, 결과물 반영자기 주장을 "채택"으로 올리지 못함 — 채택은 gate만 기록 (어기면 lint 오류)
semi-research 스킬위 절차·출처 등급·함정 체크리스트·장부 형식—
paper-scout 에이전트후보 출처 수집 (등급·접근 범위 표시)결론·종합 금지, 기억으로 DOI를 만들지 않음(학술 DB 결과만)
claim-verifier 에이전트주장을 웹 원문과 대조해 판정로컬 파일 도구 없음(웹 검색·열기만) → 작성자 메모·판단을 볼 수 없음. 작성자 근거와 다른 출처도 직접 찾음
도구 claims.pylint, blind 입력 생성, 검증 기록, gate 판정주장을 고치면 내용 해시가 바뀌어 이전 검증 자동 무효
도구 lit_search.py · check_refs.pyOpenAlex·Crossref·arXiv 검색, DOI·제목 일치·URL 확인"DOI가 있다" ≠ "내용이 맞다" — 내용은 검증자가 봄
astra (다른 계열 모델)고위험 주장 비평, 대량 추출 등 선택적으로매 질문마다 자동 호출하지 않음
jev (판단 API)범위·우선순위 같은 이산 판단증거 충돌을 종결하지 않음 — 충돌은 보류로 남기고 조건·정의·시점 차이를 조사

출처 등급 (유형이지 사실성 순위가 아님)

등급예채택 범위
T1 논문·교과서IEDM·VLSI·JVST·JAP·SPIE, 교과서원문에 명시된 조건의 결과 — 한 실험을 보편값으로 확대 금지
T2 회사·연구소TSMC·Intel·Samsung·imec 발표"그 기관이 발표했다"는 사실. 성능 우위를 사실로 쓰려면 독립 증거
T3 분석사TechInsights 등실제 열람한 직접 분석의 샘플 범위
T4 언론기사제한적. 기사 10개가 같은 보도자료면 근거는 1개
T5 루머공급망 루머, 커뮤니티탐색 단서만 — 결론에서 제외

회귀 시험 — 지난 실제 오류로 확인

#25–#38에서 실제로 나왔던 틀린 문장 6개를 원래 그대로 넣고, 맞는 문장 2개를 대조군으로 넣었다. 검증자는 별도 실행(웹 도구만 허용)으로 돌렸다.

추가 확인: R7의 문장을 한 단어 고친 뒤 다시 판정하자 "검증 후 주장이 바뀌어 재검증 필요"로 보류되고, 옛 검증 보고는 기록이 거부됨. 검증자는 원문을 못 연 경우(유료 교과서, 회사 PDF)를 판정 이유에 그대로 밝혔다.

한계

  • 검증자도 같은 계열 모델이라 오류가 통계적으로 독립이라고 보장하지는 못한다 — 고위험 주장은 다른 계열(astra) 비평을 추가로 받는다.
  • 유료 논문·분석 보고서는 원문을 못 여는 경우가 많다. 그때는 "초록만/메타데이터만"으로 표시하고 본문 조건까지 확인한 것으로 쓰지 않는다.
  • 장부(ledger/)는 원문 발췌가 들어갈 수 있어 공개하지 않는다. 공개 결과물에는 재서술한 주장과 링크만.
