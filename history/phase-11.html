#48

프로젝트 전체 구성 검토 · 재정비 계획

2026-10-12 06:49

지시 (원문)

이제 이 프로젝트의 전체 구성에 대해 고민해줘.

분석 (Claude의 정리)

  • 결과물이 14개로 늘었는데 목차는 최근순 나열뿐이다. 학습 순서와 주제 묶음이 없다.
  • 데이터가 HTML 안에 박혀 있다: 지식 그래프 232KB, 질의응답 페이지 1MB. 그래프·용어집 갱신은 저장소 밖 임시 스크립트 29개가 HTML을 정규식으로 고쳐 왔다 → 다시 만들 수 없다.
  • 용어가 세 곳에 흩어져 있다: 그래프 용어집 254, 질의응답 용어 사전 649, OES 화학종. 검증 체계는 #39 이후 작업에만 적용됐고, 초기 보고서·학습 노트·그래프에는 주장 장부가 없다.
  • 그 밖: 그래프 페이지 제목이 아직 "Apple A20 …"인데 내용은 플라즈마·패터닝·OES까지 넓어졌다. 스크린샷이 20MB(PNG)다. 작업 규칙 문서는 12.6KB로 규칙과 사용법이 섞여 있다. 법적 검토의 "중간" 위험 2건은 아직 결정되지 않았다.
  • "고민해줘"이므로 이번에는 진단과 계획까지 한다. 실행은 사용자 결정 후에 한다.

과정

  1. 06:49 현황 측정: 저장소 파일 크기, 목차 구성, 임시 스크립트 수(29), 스크린샷 65장 20.1MB(JPEG 변환 시 약 8.5MB), 공개 페이지의 주장 ID 연결 0건.
  2. 06:50 개선안 7개를 정리해 astra(xhigh)에 비평 요청(백그라운드). 개선안: 영역별 목차, 데이터 원본 분리 + 빌드 도구, 용어 단일 등록부, 검증 소급, 법적 위험 조치, 운영 정리, 그래프 이름.
  3. 06:51 jev 자문 4건
    · 가장 먼저 할 일 → 데이터 원본 분리(선택 b, 확률 0.54, 신뢰도 0.42 — 낮음)
    · URL 유지 → 0.46(애매)
    · 법적 조치는 사용자 결정 → 0.70
    · 이번 대응 → "위험 낮은 것은 바로 실행" 0.57 대 "제안만" 0.43
    마지막 판단은 반영하지 않았다: 지시가 검토 요청이고, astra도 1순위를 사용자 결정 사항(공개 범위)으로 꼽았기 때문이다.
  4. 06:52 astra 비평 수신.
    · 방향은 타당하다. 순서는 "공개 범위 확정 → 재현 가능한 생성 경로 → 핵심 주장 검증 → 탐색 개선 → 운영·성능".
    · 줄일 것: 허브 페이지 5개 대신 목차 안 5개 섹션. 용어 649개를 한 번에 정규화하지 말 것. 이미지 변환만 하려고 이력을 재작성하지 말 것.
    · 더할 것: 페이지 목록(pages.json)과 가벼운 검색. 페이지 전체 배지 대신 주장별 상태·검토일. "한 표기 = 한 ID"가 아니라 "한 개념 = 한 ID". 구조 이관과 내용 수정은 따로 커밋. 새 clone에서 한 명령으로 재생성되는지를 완료 기준으로.
    모두 계획에 반영했다.

결과 / 증거

계획 수립 5단계 재정비 계획 (실행은 사용자 결정 후)

  1. 공개 범위 확정: 질의응답 글별 요약, 교과서 표 → 유지 / 축소 / 보류 (사용자 결정)
  2. 재현 가능한 생성 경로: kb/ 원본 JSON + tools/build_site.py. 그래프·용어집 → OES 순서. 완료 기준: 새 clone에서 한 명령으로 재생성.
  3. 핵심 주장 20~30개 검증 소급: 주장별 상태·검토일 표시
  4. 목차 5개 섹션 + 학습 경로 + 가벼운 검색: 학습 경로는 플라즈마 원리 → 식각 화학·OES → DPT·QPT → GAA/A20. 그래프 제목을 "식각 지식 그래프"로.
  5. 운영: 빌드·링크 자동 점검, 짧은 규칙 문서 + runbook, 성능 측정 후 최적화
