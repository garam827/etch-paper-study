# semi-research — 반도체 지식·논문 탐색·검증 절차

이 스킬은 "찾기 → 주장 장부 → 독립 검증 → 규칙 기반 채택"을 반복 가능하게 만든다.
규칙의 근거와 세부 기준은 같은 폴더의 `policy.md`(출처 등급·함정 체크리스트)와 `schema.md`(장부 필드)에 있다. 시작 전에 둘 다 읽는다.

## 역할

| 누구 | 하는 일 | 하지 않는 일 |
|---|---|---|
| Claude (조율·작성) | 질문 정리, 장부 작성, 결과물 반영 | 자기가 쓴 주장을 스스로 "확인됨"으로 올리기 |
| `paper-scout` 에이전트 | 중립 질문만 받고 후보 출처 수집 | 결론·종합 |
| `claim-verifier` 에이전트 | 장부의 `blind` 입력만 받고 원문 대조 | 장부·파일 읽기/수정 (웹 도구만 가짐) |
| `tools/claims.py` | 단위·날짜·조건 lint, 해시, 채택 판정(gate) | — |
| astra (Codex, high/xhigh) | 다른 모델 계열의 독립 리서치·고위험 주장 비평 | 매 질문마다 병렬 호출 (선택적으로만) |
| jev | 범위·우선순위 같은 이산 판단 | **증거 충돌의 종결** (충돌은 보류로 남김) |

## 절차

1. **질문 정리** — 하위 질문, 기준일(as_of), 결과가 쓰일 곳(보고서·용어집·그래프), 고위험 주장(결론을 좌우하는 수치·날짜·비교)을 적는다.
2. **수집** — `paper-scout`에 *중립 질문만* 준다(작성자의 가설·기대 답 금지). 동시에 학술 메타데이터 검색:
   `python tools/lit_search.py "<영문 키워드>" --n 10 --from 2015`
   필요하면 astra high를 백그라운드로 (`run_in_background`).
3. **장부 작성** — `ledger/<주제>.json`. 주장은 원자적으로(한 문장 = 한 사실), 수치는 단위·조건·모델 가정과 함께, 날짜는 사건 종류(발표·샘플·양산·출하·분석)와 함께. 원문을 실제로 본 범위를 `access_level`로 정직하게.
4. **기계 검사** —
   `python tools/claims.py lint ledger/<주제>.json` (오류 0이 될 때까지 고침)
   `python tools/check_refs.py ledger/<주제>.json` (DOI·URL 실재. *내용 검증이 아님*)
5. **독립 검증** — `python tools/claims.py blind ledger/<주제>.json > <scratchpad>/blind.json` 의 내용을 그대로 `claim-verifier`에 넘긴다. 작성자 메모·발췌·판단은 넘기지 않는다. 고위험 주장은 검증자가 작성자 근거와 별도로 출처를 찾게 한다.
   돌아온 판정 JSON을 손대지 않고 파일로 저장 → `python tools/claims.py record ledger/<주제>.json <판정.json>`
6. **채택** — `python tools/claims.py gate ledger/<주제>.json`. 결정은 gate만 한다.
   - `adopt` → 그대로 사용 / `conditional` → 조건·"단일 출처"를 문장에 넣어 사용 / `hold` → 쓰지 않거나 "확인 중"으로 / `reject` → 쓰지 않음
   - 판정 충돌(`hold`)은 조건·정의·시점 차이를 먼저 조사한다. 그래도 남으면 결과물에 "출처 간 불일치"로 표시. 아주 중요하면 astra xhigh 비평을 받되, 그 의견도 장부의 근거로 기록할 뿐 자동 채택하지 않는다.
7. **수정하면 재검증** — 주장 문장·조건·수치·근거 위치를 고치면 내용 해시가 바뀌어 이전 검증은 자동 무효. 5단계부터 다시.
8. **반영·기록** — 결과물에는 채택된 주장만, 주장 ID와 출처 링크를 함께. 작업 기록(history)의 "과정"에 lint·gate 결과 요약(채택/조건부/보류/제외 개수)을 남긴다.

## 회귀 확인

체계를 고친 뒤에는 `tools/tests/regression_ledger.json`(지난 실제 오류 6개 + 정상 2개)로 lint가 단위 오류를 잡는지, 검증·gate가 틀린 주장을 막고 정상 주장을 통과시키는지 확인한다.

## 비공개

`ledger/`(유료 원문 발췌가 들어갈 수 있음), 원본 리서치·로그는 공개 저장소에 올리지 않는다(.gitignore). 공개 결과물에는 재서술한 주장과 링크만.
