Claude · Codex · jev 자문 에이전트 — 구조와 사용법

이 프로젝트가 실제로 쓰고 있는 방식 그대로 정리 · 2026-10-05

한 장 요약

사용자가 한국어로 지시하면 Claude Code가 일을 맡아 진행한다. 혼자 결정하지 않고, 일의 종류에 따라 다른 AI에게 자문을 구한다. 조사는 gpt-6-astra에게 맡기고, 판단은 jev에게 묻는다. 모든 과정은 history.html에 기록되고 GitHub Pages로 공개된다. 이 규칙은 전부 CLAUDE.md 한 파일에 적혀 있어서, Claude Code가 이 폴더에서 시작할 때마다 자동으로 읽는다.

사용자
지시 · 승인
  • 할 일을 말로 지시
  • 공개 게시·강제 푸시 같은 되돌리기 어려운 일을 승인
  • 판단이 갈릴 때 최종 결정
Claude Code
지휘 · 실행 · 기록
  • 지시를 해석하고 작업을 쪼갬
  • 자문 호출, 파일 작성, 검증
  • history 기록, 민감정보 검사, 배포
gpt-6-astra
Codex CLI로 호출
  • high + 웹 검색: 리서치 (백그라운드)
  • xhigh: 아주 중요한 판단
  • 긴 서술형 답변
jev
TypeSafe 판단 API
  • 일반 판단 (예/아니오, 선택, 점수)
  • 정해진 형식으로 확률·신뢰도를 돌려줌
  • 빠르고 쌈

구조도

Claude Code는 다른 AI를 직접 부르는 기능을 쓰지 않는다. 터미널 명령(Bash)으로 Codex CLI와 Python 스크립트를 실행하고, 그 출력을 읽는 단순한 방식이다. 그래서 별도 서버나 프레임워크 없이 동작한다.

누구에게 물을지 정하는 규칙

상황보내는 곳호출 방식돌려받는 것이 프로젝트의 예
리서치가 필요할 때gpt-6-astra high백그라운드 실행 + 웹 검색. 기다리는 동안 다른 일 진행출처가 달린 긴 보고서 (마크다운)TSMC N2 · A20 공정 조사 (약 10분, 검색 44회, 출처 32개)
일반 판단이 필요할 때jev즉시 실행 (수 초)선택 결과 + 확률 + 신뢰도"A20"의 뜻, 보고서 무게중심, 공개 범위, 페이지 구성
아주 중요한 판단gpt-6-astra xhigh즉시 실행 (깊게 생각하므로 느림)근거를 단 서술형 의견(아직 사용 사례 없음)
되돌리기 어려운 일사용자Claude가 멈추고 질문승인 또는 다른 지시공개 저장소 생성, 강제 푸시

원래 리서치는 gpt-6.1-sol에 맡기기로 했으나, 이 계정의 Codex에서는 지원되지 않아 사용자 지시로 gpt-6-astra high로 바꿨다.

따라 하기

먼저 알아둘 것. 이 구성은 유료 계정 세 개를 씁니다: Claude Code, ChatGPT(Codex CLI 로그인용), TypeSafe(jev, 최소 $5 충전). jev 요금은 입력 100만 토큰당 $0.042이고 출력은 무료입니다 (참고 글 기준). 모델 이름(gpt-6-astra 등)은 계정마다 쓸 수 있는 것이 다를 수 있습니다.

  1. 도구 설치

    Claude Code, Codex CLI, Python 3, (공개하려면) Git과 GitHub CLI.

    npm install -g @openai/codex
pip install requests python-dotenv

  2. Codex 로그인과 모델 확인

    ChatGPT 계정으로 로그인한 뒤, 쓸 모델이 실제로 응답하는지 짧게 시험합니다.

    codex login
codex exec --skip-git-repo-check -s read-only -m gpt-6-astra \
  -c model_reasoning_effort='"high"' "Reply with exactly: PONG" </dev/null

    끝의 </dev/null을 빼면 Codex가 추가 입력을 기다리며 멈춥니다.

  3. jev 키 넣기

    TypeSafe에서 API 키를 발급받아 프로젝트 폴더의 .env에 한 줄로 넣습니다. =는 하나만 씁니다.

    TYPESAFE_API_KEY=발급받은_키

    .env는 반드시 .gitignore에 넣어 저장소에 올라가지 않게 합니다.

  4. jev 호출 도우미 준비

    이 저장소의 tools/ask_jev.py를 복사합니다. 질문을 JSON 파일로 만들어 넘기면 됩니다.

    {
  "state": "지금 상황 설명 (무엇을 하고 있고 무엇을 정해야 하는지)",
  "questions": {
    "next_step": {
      "type": "choice",
      "instructions": "다음으로 가장 먼저 할 일은?",
      "criteria": { "collect": "논문 목록 수집", "plan": "계획 수립" }
    },
    "need_confirm": { "type": "noul", "instructions": "사용자에게 먼저 확인해야 하는가?" }
  }
}
    python tools/ask_jev.py question.json

    답은 이렇게 옵니다:

    "next_step": { "choice": "collect", "confidence": 0.59,
               "probabilities": { "collect": 0.73, "plan": 0.2 } },
"need_confirm": { "noul": 0.91 }

  5. CLAUDE.md에 규칙 적기

    Claude Code가 매번 따르게 할 규칙을 프로젝트 폴더의 CLAUDE.md에 씁니다. 핵심은 이 세 줄입니다. 전체 예시는 이 저장소의 CLAUDE.md를 참고하세요.

    1. 리서치가 필요할 때 → gpt-6-astra (high)를 백그라운드로 호출한다.
2. 판단이 필요할 때 → jev에게 묻는다.
3. 아주 중요한 판단 → gpt-6-astra (xhigh)에게 자문받는다.

    같은 파일에 호출 명령, 기록 규칙(history.html), 민감정보 금지 규칙도 함께 둡니다.

  6. 평소처럼 지시하기

    프로젝트 폴더에서 Claude Code를 켜고 하고 싶은 일을 말로 지시합니다. 누구에게 물을지는 Claude가 규칙에 따라 정합니다.

    "TSMC 2nm A20 공정을 Wafer IN부터 OUT까지 조사해줘"   → astra 리서치
"이 결과를 어디에 두는 게 좋을까?"                     → jev 판단
"결과 나오면 보고서랑 history 정리해줘"                 → Claude 실행 · 기록

  7. (선택) 공개하기

    공개 저장소를 만들고 GitHub Pages를 켭니다. 첫 공개 전에 커밋 메일을 GitHub no-reply 주소로 바꿔두세요.

    git config --local user.email "<id>+<계정>@users.noreply.github.com"
gh repo create <이름> --public --source . --push
gh api -X POST "repos/{owner}/<이름>/pages" -f "source[branch]=main" -f "source[path]=/"

실제로 겪은 문제와 해결

문제gpt-6.1-sol을 부르니 "ChatGPT 계정으로는 Codex에서 지원되지 않는 모델" 오류
해결짧은 시험 호출로 미리 확인. 리서치 담당을 gpt-6-astra high로 교체
문제Codex 호출이 아무 응답 없이 멈춤 ("Reading additional input from stdin...")
해결모든 호출 끝에 </dev/null을 붙여 입력을 닫음
문제jev가 401 인증 실패
해결키 값은 보지 않고 형식만 검사 → TYPESAFE_API_KEY==...처럼 =가 두 번. 사용자가 직접 수정
문제API 키를 외부로 보내는 호출, 강제 푸시가 Claude Code 자동 모드에서 차단됨. 채팅으로 "허용한다"고 해도 풀리지 않음
해결Claude가 우회하지 않고 멈춤. 사용자가 자동 모드를 끄고(Shift+Tab) 권한 확인창에서 승인
문제공개 후 점검에서 커밋 작성자에 개인 메일 주소가 드러남
해결no-reply 주소로 기록을 다시 써서 강제 푸시. 단, GitHub은 교체된 옛 커밋을 ID로 한동안 계속 보여줌 → 저장소 재생성 또는 GitHub 지원 요청이 필요. 처음부터 no-reply로 시작하는 것이 정답

구조 분석

잘 되는 점약한 점
  • 역할 분리: 긴 조사는 웹 검색이 되는 astra, 빠른 판단은 형식이 정해진 jev. 각자 잘하는 일만 맡음
  • 비동기 리서치: 10분짜리 조사를 기다리는 동안 jev 판단과 사용자 확인을 먼저 끝냄
  • 규칙이 한 파일: CLAUDE.md만 고치면 동작이 바뀜. 서버·프레임워크 없음
  • 숫자로 남는 판단: jev는 확률을 주므로 "왜 그렇게 했는지"가 기록에 남음
  • 사람이 마지막 관문: 되돌리기 어려운 일은 권한 검사가 멈춰 세움
  • 검증 부족: astra 보고서는 출처를 달지만 Claude가 원문을 다 대조하지는 않음 (A20 건은 1개만 확인)
  • jev 신뢰도 기준 없음: 0.56처럼 애매한 답도 그대로 따름. 낮으면 astra나 사용자에게 올리는 기준이 필요
  • 비용·호출 기록 없음: 토큰 사용량을 모아 보지 않음
  • 모델 이름 의존: 계정·시점에 따라 모델이 사라지거나 바뀔 수 있음
  • 기록이 수작업: history 항목을 매번 손으로 추가 → 빠뜨릴 위험

개선 제안

  1. 신뢰도 기준 추가: jev 신뢰도가 0.6 미만이거나 두 선택지 확률 차가 작으면 astra xhigh 또는 사용자에게 올린다.
  2. 교차 검증: astra 리서치의 핵심 주장 3~5개는 Claude가 원문을 열어 대조하고, 결과를 보고서에 표시한다.
  3. 호출 래퍼: Codex 호출도 tools/ask_astra.sh 같은 스크립트로 묶어 옵션 실수(</dev/null 누락 등)를 막고, 사용량을 한 파일에 쌓는다.
  4. 기록 자동화: 항목 추가를 스크립트로 만들어 형식을 통일하고 민감정보 검사를 함께 돌린다.

이 페이지는 Claude Code가 이 프로젝트의 실제 작업 기록(history)을 바탕으로 작성했다. 구성은 jev의 판단(사용법 위주 0.58, 겪은 문제 포함 0.66, 실제 예시 포함 0.79)을 따랐다.
